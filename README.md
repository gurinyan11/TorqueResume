# Torque Resume

Torque Resumeは、Androidの「最近使ったアプリ」画面から **Torque Proのカードを選択し、既存の画面に復帰させる**ために開発した補助アプリです。

ATOTO S8MS（Android 10）で復帰動作を確認した試作の完成版を、開発・検証記録として保全するためのリポジトリです。

最終的には、Torque Pro自身が必要な状態値を保持できることが確認され、Torque Resumeを実運用する必要がなくなったため、不採用となりました。

## 開発の背景

ATOTO S8MSでTorque Proを使用する際、ナビゲーションなどの他のアプリからTorque Proに戻る方法によって、表示状態に違いが見られました。

当初の実機試験では、次の現象を確認しました。

- Torque Proをバックグラウンドにした際、ECUとの通信は継続しているように観測された。
- Androidの「最近使ったアプリ」画面からTorque Proを選択すると、それまでの表示値が保持されていた。
- Torque Proのアイコンから起動すると、FrontPageを経由し、表示やセッション値がリセットされる現象があった。

このため、**Torque Proを新規起動せず、既存のタスクを履歴画面から復帰させる方法**を検討しました。

履歴画面を手動操作する代わりに、その操作を自動化する目的で開発したのがTorque Resumeです。

### 当初の検証で残された疑問

履歴画面から復帰した際に表示値が保持されていても、バックグラウンド中のデータ取得・積算が継続していたとは限りません。

当時、ChatGPTからもこの点について指摘がありました。

- 履歴画面から復帰して表示値が保持されることは確認した。
- バックグラウンド中のECU通信は継続しているように観測された。
- **その間のデータが欠落なく取得・積算されていたかは未確認だった。**

したがって、表示状態の保持を、データ取得・積算の連続性が保証された証拠として扱うことはできません。

## 動作

1. Torque Resumeを起動します。
2. Androidのアクセシビリティサービスを使い、「最近使ったアプリ」画面を表示します。
3. 約1秒後、画面内のテキストまたはコンテンツ説明からTorqueのカードを探します。
4. 該当するカード、またはクリック可能な親要素を選択します。
5. 処理後、Torque Resume自身の画面を終了します。

**動作の前提：Torque Proが既に起動しており、バックグラウンドに回っていても、Androidの「最近使ったアプリ」画面にTorque Proのカードが残っていること。**

カードをアクセシビリティ経由で検出・選択できる必要があります。

**Torque Proを新規起動するアプリではありません。**

## 動作環境・権限

- 実環境：ATOTO S8MS（Android 10）
- 開発・ビルド環境：AndroidIDE
- Androidアプリの設定：`minSdk 23`、`targetSdk 35`
- 必要な設定：Androidの設定画面でTorque Resumeのアクセシビリティサービスを有効化

アクセシビリティサービスが利用できない場合は、エラーを表示してアクセシビリティ設定画面を開きます。

## 制約

- 最近使ったアプリの画面構成や、カードに付与される文字列・説明に依存します。
- 検索対象は`torque`または`torque pro`に一致する文字列です（大文字・小文字は区別しません）。
- カードを検出できなかった場合はメッセージを表示します。自動再試行は実装していません。
- 約1秒の待機時間は固定です。
- 他のAndroid端末・OS・ランチャーでの動作は保証しません。
- Torque Proのバックグラウンド中のデータ取得・積算の連続性を保証する機能はありません。

## 実機試験で判明した問題

以下は、開発時の実機試験で確認した事象です。原因や解決状況が確定していないものは、そのまま区別して記録します。

### テスト機のUI表示崩れ

テスト機TB320では「最近使ったアプリ」画面のUIが崩れる問題が発生しました。

原因は未確定です。

### アクセシビリティサービス設定直後の動作

アクセシビリティサービスを有効化しただけでは機能せず、別の設定画面へ遷移する操作が必要でした。

この操作が必要となる原因は確定していません。

### ATOTO S8MSのロングスリープとADB

S8MSでは、ロングスリープのたびにADBの設定もリセットされました。

このため、ADBを利用したアクセシビリティサービスの復旧策は、継続運用の方法として使えないと判断しました。

## 最終的な評価

Torque Resumeによる履歴画面からの復帰処理は、実装と動作確認に成功しました。

しかし、実機試験ではUI表示、アクセシビリティサービス、ロングスリープ後の設定維持に関する問題がありました。

さらに、その後の検証で**Torque Pro自身が必要な状態値を保持できることが判明し、Torque Resumeを使用する必要性そのものがなくなりました。**

ただし、ここで確認された状態値の保持は、バックグラウンド中のデータ取得・積算が欠落なく継続したことを意味しません。この点は未検証事項として残します。

最終判断は以下のとおりです。

- **技術的結果：** 履歴画面からのTorque Pro復帰処理は成功。
- **運用上の評価：** 端末固有の問題や設定維持の課題あり。
- **必要性の評価：** Torque Pro自身の状態保持を確認したため、復帰処理は不要。
- **最終判断：** 実運用には採用せず、試作と検証の記録として保存。
