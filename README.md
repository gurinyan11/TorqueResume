# Torque Resume

Torque Resume は、Android の「最近使ったアプリ」画面から **Torque Pro のカードを選択し、画面に復帰させる**ための補助アプリです。

ATOTO S8MS の実環境で復帰処理の動作を確認した版を、試作・検証の記録として保全するリポジトリです。最終的には Torque Pro 自身が必要な状態値を保持できると判明したため、Torque Resume は実運用に採用しませんでした。追加開発・不具合修正は予定していません。

## 動作

1. Torque Resume を起動します。
2. Android のアクセシビリティサービスを使い、「最近使ったアプリ」画面を表示します。
3. 約1秒後、画面内のテキストまたはコンテンツ説明から Torque のカードを探します。
4. 該当するカード、またはクリック可能な親要素を選択します。
5. 処理後、Torque Resume 自身の画面を終了します。

**動作の前提：Torque Pro が既に起動しており、バックグラウンドに回っていても、Android の「最近使ったアプリ」画面に Torque Pro のカードが残っていること。** カードをアクセシビリティ経由で検出・選択できる必要があります。

**Torque Pro を新規起動するアプリではありません。**

## 動作環境・権限

- 実環境：ATOTO S8MS（Android 10）
- 開発・ビルド環境：AndroidIDE
- Android アプリの設定：`minSdk 23`、`targetSdk 35`
- 必要な設定：Android の設定画面で Torque Resume のアクセシビリティサービスを有効化

アクセシビリティサービスが利用できない場合は、エラーを表示してアクセシビリティ設定画面を開きます。

## 制約

- 最近使ったアプリの画面構成や、カードに付与される文字列・説明に依存します。
- 検索対象は `torque` または `torque pro` に一致する文字列です（大文字・小文字は区別しません）。
- カードを検出できなかった場合はメッセージを表示します。自動再試行は実装していません。
- 約1秒の待機時間は固定です。
- 他のAndroid端末・OS・ランチャーでの動作は保証しません。

## 実機試験で判明した問題

以下はソースコードの仕様ではなく、開発時の実機試験で確認した事象です。原因や解決状況が確定していないものは、そのまま区別して記録します。

- **テスト機のUI表示崩れ**：テスト機では「最近使ったアプリ」画面のUIが崩れる問題が発生しました。原因は未確定です。
- **アクセシビリティサービス設定直後の動作**：サービスを有効化した後、そのままでは機能せず、別の設定画面に遷移する操作が必要でした。原因は未確定です。
- **ATOTO S8MSのロングスリープとADB**：ロングスリープのたびにADBの設定もリセットされるため、ADBを利用したアクセシビリティサービス復旧策は実用にならないと判断しました。

## 最終的な評価

復帰処理そのものは実装・動作確認できました。しかし、実機のUI・アクセシビリティ・ロングスリープに関する運用上の問題がありました。さらに、**Torque Pro自身が必要な状態値を保持できることが判明し、復帰処理の必要性そのものがなくなりました。**

したがって、Torque Resumeは**技術的には動作したものの、実運用では不要と判断した試作**です。このリポジトリは、採用済みの運用ツールではなく、その検証結果と完成時点のソースを残すためのものです。

## ソースコード

主要な実装は以下の2ファイルです。

- `app/src/main/java/jp/jm23/recentsbutton/MainActivity.java` — 起動、復帰処理の呼び出し、終了
- `app/src/main/java/jp/jm23/recentsbutton/RecentsAccessibilityService.java` — 最近使ったアプリ画面の表示、Torqueカードの探索と選択

ソースは実環境で動作した版をそのまま保存しています。アプリ名は Torque Resume ですが、内部のパッケージ名とGradleプロジェクト名には開発時の `recentsbutton` / `RecentsButton` が残っています。
